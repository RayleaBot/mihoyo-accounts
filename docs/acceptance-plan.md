# 验收与交付计划

本计划承接主仓库 RayleaBot 的游戏插件返工计划中尚未完成的 R7 阶段（验收与交付）；R0 至 R6c 已完成，其内容随主仓库文档删除，不再保留。记录日期：2026-10-02。

## 验收口径

- 用户可见功能以 Windows 实例上的 Core、真实账号和真实聊天消息验收，并与上游同一命令的输出对照；合成数据测试只用于回归，不能替代验收。
- 对照的上游仓库与固定提交见 [DATA_SOURCES.md](../DATA_SOURCES.md)。
- 与上游有意不同的行为见文末一节，对照时不算缺陷。
- 验收结束时提交本仓库，不推送。

## 待验收事项

- 账号库：只能由管理员在管理页初始化并选择模式，Windows 可在 DPAPI 与口令之间互相切换、切换后原有账号可读，非 Windows 只提供口令模式；未初始化时聊天 `#扫码登录` 只提示管理员先完成设置。
- 扫码登录：私聊与群聊 `#扫码登录`（群聊 @ 发起人，二维码发出 30 秒后撤回，结果回到发起的聊天）、`#登录状态`、`#取消登录`、管理页“扫码添加账号”；登录成功的角色图（Miao-Yunzai 的 uid-list，按三游戏列出 UID、CK 标记、名称等级、头像与横幅，无法出图时回复文字）；扫码结果按 `token_type` 识别 SToken；结果送出后删除每分钟的通知任务。
- CK 命令：`#我的CK`（群聊回复“请私聊查看”）、`#检查CK [序号]`、`#刷新CK [序号]`（重新换取 LToken 与 Cookie Token 并重读三游戏角色，读取失败的游戏保留原有角色，后台事件）、`#删除CK [序号]`；不分大小写并接受 cookie 写法；`#体力帮助`、`#CK帮助`、`#绑定CK`、`#CK代码` 回复扫码登录用法。
- 导入：管理页按地区的 Cookie 导入（国服接受 SToken 或 LToken 与 CookieToken，与扫码得到的同一通行证合并）；管理页加密导入设备信息。
- 设备：`#绑定设备`、`#绑定设备帮助`、`#解绑设备`（私聊收到的设备信息直接加密保存，绑定持有当前绝区零 UID 的账号；解绑后换用默认设备或自动生成的设备）、默认设备（绝区零插件的 `%设置默认设备` 经本插件保存，供没有自己设备的账号使用）；设备指纹登记字段与 ZZZ-Plugin 一致，之后的请求按设备品牌与型号标注。
- 服务：`accounts` v1 的固定操作表与端点主机白名单，查询与抽卡分页转发官方 data、只删除凭据字段、值中出现凭据时拒绝；挑战查询的 `need_all: false` 与异相仲裁的 `peak_period`；幽境危战人气查询；monthly 只读委托（超级管理员可列出全部账号）与 billing 只读委托（读不完时在调度任务中继续）；`uids.current` 返回被 @ 用户当前使用的 UID 与无 CK 的 UID 绑定；`gacha.link`；ark 令牌加密保存、`ark.request` 代发与 `ark.status`；挑战提醒委托（同一任务按操作各持一项）；公共查询池（由 CK 主人逐个开启并带每日额度，公共账号连读首页与角色列表）；授权撤销与默认指定的三个游戏插件。
- 凭据提示：聊天中识别 Cookie、SToken 与登录票据时提示撤回并改用扫码登录或管理页加密导入；抽卡链接不再提示。
- 默认关闭的保留功能：米游币与社区任务、云游戏签到，以及云游戏令牌的加密存储。
- 清单与 SDK 注册的服务方法一致（以测试核对）。

## 受限事项

- 海外账号：海外导入、认证、固定端点与设备验证尚无真实海外账号验收。
- 云游戏独立授权：需要独立的 `x-rpc-combo_token`，上游说明要求云客户端授权，没有以米游社凭据换取的已验证路径；云钱包 GET 可能同时发放免费时长，按有副作用处理。
- 国服网页兑换：没有已验证的国服网页兑换入口，兑换属游戏插件，本插件只代发请求。
- Linux 与 macOS：实机未验收，只有口令模式。

## 与上游的有意差异

- 账号库只能由管理员在管理页初始化与切换模式，聊天命令不触发初始化；非 Windows 只有口令模式。
- 只有 `#我的CK` 在群聊强制私聊，其他账号命令在群聊可用；扫码登录在群聊 @ 发起人并随后撤回二维码。
- CK 与 SToken 不在聊天中接收，只经扫码登录或管理页加密导入；聊天中出现凭据时提示撤回。
- 不提供密钥轮换、加密备份与跨机分块迁移；口令模式下迁移机器直接拷贝数据库与数据目录。
- 代理请求只有固定操作表，调用方不能自选端点；字段筛选、抽卡记录归一与业务时区由游戏插件负责。
