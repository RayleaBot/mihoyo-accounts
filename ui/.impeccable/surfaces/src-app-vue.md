# 账号管理

- 范围：插件唯一的管理页“账号管理”（`src/App.vue` 及其组件），按机器人账号显示；账号库、密钥保护与 ark 令牌是同页的全局设置。
- 模式：Operate。
- 用户与任务：机器人管理员认出每个账号属于哪位聊天用户，判断能否使用，检查、刷新、补绑或清理；偶尔调整账号库与 ark 令牌。
- 约束：动作、请求参数与凭据加密流程不变；QQ 昵称只在机器人在线时经宿主身份接口读取，读取失败时以 QQ 号显示；QQ 官方机器人的用户只有 openid，没有头像与昵称。
- 本轮未经用户选择方向：按掷骰分配的方向无人值守构建；竞争方向“角色周边目录”（以头像为主的圆润名册，受众认同更强、信息清晰度较弱）留作备选。
- 用户指定（2026-10-12）：管理与添加账号改为弹出式独立窗口，不在页面中占位；交互与动画要流畅。
- 待定：是否把同一用户的多个账号合并成一张名片（当前按账号一张、同一用户相邻）。

## Direction contract

THESIS：每个已绑定的通行证是一张名片：QQ 头像与昵称领头，米游社 / HoYoLab 通行证是所属机构，游戏角色是头衔。页面是一本名片册，拒绝“账号表格加状态列”的默认排法。

OWN-WORLD：冷灰册页上的白卡纸名片，细边加贴近纸面的短投影；近黑墨色，唯一专色米游社蓝只给主操作、取出的名片与焦点；需要处理的名片上缘插着带字索引贴（朱红为需重新登录，琥珀为待检查或需验证）；数字等宽右对齐。

STORY：管理员先认出人，再看角色与可用性；索引贴挑出要处理的名片，取出名片在弹出窗口里处理，勾选多张后底部出现批量操作条。

FIRST VIEWPORT：顶部一条下一步提示带（一句话、一个动作）；其下是索引页签（全部 / 需处理 / 可用）、搜索与主操作“扫码添加账号”；主体是占满宽度的三到四列名片网格；管理与添加账号是遮罩上的弹出窗口，取出的名片在窗口里放大，背面列出角色、设备、云授权与授权插件；账号库与设置在册子末页。

FORM：名片册，grounded list 第 7 位，seed key dcaa44f9。招牌交互“取出名片”：view transition 让名片从格位飞进弹出窗口，遮罩淡入、窗口上浮，关闭时原路飞回；reduced-motion 下直接切换。

RAISES：
- 字体样张：层级只靠字号对比，昵称是每张名片上最大的字，不用装饰或图标排序。
- 单色画布：每个状态附带证据，检查或刷新的结果与时间印在名片正面。
- 磁带封面：QQ 号、UID、等级与计数用等宽数字右对齐，跨名片成列。
- 机场导视：顶部只有一条下一步提示带，一句话、一个动作。
- 定向越野图：颜色语言固定且保留，专色只给主操作、取出的名片与焦点，红与琥珀只出现在索引贴上。
