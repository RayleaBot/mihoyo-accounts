# 米游社账号插件

独立的 RayleaBot 原生 Go/Vue 插件，提供米游社扫码登录、加密账号库、三游戏角色发现和 `accounts` v1 服务。要求包含通用插件服务能力的 RayleaBot Core。

## 使用

1. 打开插件的“账号管理”，初始化账号库。Windows 可使用当前用户的 DPAPI，其他系统使用恢复口令；之后可在“密钥保护方式”中切换。账号库只能由管理页初始化，聊天中的 `#扫码登录` 在初始化前只会提示管理员先完成设置。
2. 点击“扫码添加账号”，选择在线机器人并填写聊天用户 ID，使用米游社扫码确认。也可在机器人私聊发送 `#扫码登录`。
3. 账号保存后，原神、星穹铁道、绝区零插件通过业务服务使用账号。默认指定 `raylea.genshin`、`raylea.starrail`、`raylea.zzz`，可在单个账号的“管理”中撤销授权。

命令前缀沿用宿主设置，以下使用 `#` 举例：

| 私聊命令 | 行为 |
| --- | --- |
| `#扫码登录` | 使用米游社创建绑定任务 |
| `#登录状态` | 查询进度，完成账号保存 |
| `#取消登录` | 取消本人的当前任务 |
| `#我的CK` | 查看脱敏账号与角色状态 |
| `#检查CK [序号]` | 检查已保存登录状态，不换取凭据，默认第一个 |
| `#刷新CK [序号]` | 重新换取指定账号的 LToken 与 Cookie Token，默认第一个 |
| `#删除CK [序号]` | 移除指定账号，默认第一个 |
| `#绑定设备` / `#绑定设备帮助` / `#解绑设备` | 出现 10041 时按 ZZZ-Plugin 绑定设备：私聊发送“绑定设备”后，两分钟内私聊发送设备标识与指纹（`{"device_id","device_fp"}`）或安卓设备信息工具复制的内容，发送“取消”放弃；绑定持有当前绝区零 UID 的账号，国际服不需要绑定。管理页“设备信息与重置”也可加密导入。解绑清除导入的设备并换用新的设备标识，之后使用默认设备（已设置时）或自动生成的设备。超级管理员在绝区零插件私聊“设置默认设备”后发送安卓设备信息，即加密保存为默认设备，供没有自己设备的账号使用。 |

CK 命令与上游一样不分大小写，也可写作 cookie（`#我的cookie`、`#删除ck`），`#ck`、`#ck状态` 与 `#我的ck状态` 同 `#检查CK`。Yunzai 的 `#体力帮助`、`#CK帮助`、`#绑定CK` 与 `#CK代码` 用于说明粘贴 Cookie 的绑定方法，这里回复扫码登录的用法，群聊中也可发送。

聊天扫码由每分钟任务检查并发送结果，全部结果送出后删除该任务；“登录状态”可立即查询。进程重启后，未保存的扫码任务失效。已有账号保留。角色发现失败可按游戏重试，不要求重新扫码。

CK 命令兼容大小写。三个游戏共用加密保存的设备指纹；已有账号在下一次查询自动补齐指纹，无需重新扫码。接口拒绝会保留错误码，只有明确凭据失效才提示重新登录。

## 账号维护与统计

账号卡片的“检查状态”通过固定官方角色绑定接口验证本次登录可用性，不换取 Token、不覆盖游戏角色；没有原神角色的空列表也可通过检查。游戏设备验证与 SToken 可用性仍需分别判断。“刷新凭据”才重新换取 LToken/Cookie Token。最近检查/刷新结果随账号加密保存，重新扫码清除旧检查结果。缺少 SToken 时跳过刷新并保留现有 CK 状态，不把缺少刷新材料判定为登录失效。

勾选当前页账号后，可批量检查、刷新或清理所选失效账号，每批最多 128 项。清理先显示具体名单，确认后再次核对失效状态和选择时的账号版本；刚重新登录或发生变化的账号会跳过，临时网络失败和设备验证不会导致清理。批次逐项显示结果，响应丢失可继续同一进度；关闭页面停止后续处理，已完成操作保留，空闲十五分钟过期。

“统计全部账号”分页读取已保存摘要，汇总账号、完整聊天主体、状态、各游戏角色和共享用途，不请求米游社、不刷新凭据。结果注明统计时段，并非同一时刻快照；最多 16384 个账号。刷新统计直接重读账号目录，不清除账号，也不维护第二份用户缓存。

## 数据与恢复

凭据与账号索引在插件内通过 AES-256-GCM 加密，宿主 `secret.write` 只收到加密信封。密钥文件位于宿主提供的本插件数据目录 `master-key.json`，内容由 Windows DPAPI 或恢复口令再次包装。恢复口令先用进程公钥加密，再经过管理接口；页面、普通配置、业务结果和日志不显示 CK。

备份需同时保留宿主数据库与本插件的数据目录。口令模式还需保留口令；DPAPI 模式依赖原 Windows 用户环境。恢复库缺少原密钥时拒绝初始化覆盖，不自动丢弃原数据。换机时先把保护方式切换为恢复口令，再复制宿主数据库与本插件数据目录，在新机器上用口令解锁；需要时再切回 Windows 用户保护。

所有已安装插件默认可信。指定插件名单限制正式账号接口的正常使用，沿用宿主的页面与私有命名空间，不提供抵御同系统用户恶意代码的隔离。游戏插件获得业务 DTO，不接收 CK；对米游社的凭据请求仅使用固定 HTTPS 端点。

账号服务提供原神和绝区零官方抽卡分页读取，AuthKey 只保留在本进程短期内存中，游戏插件只接收脱敏业务记录。星铁完整抽卡授权被官方拒绝时单独返回限制状态，不误判 CK 失效；星铁的跃迁记录由星铁插件读取聊天中发送的抽卡链接更新。绝区零的“获取抽卡链接”经 `gacha.link` 在本人私聊中取得链接，这是 AuthKey 离开本插件的唯一途径。

游戏插件可显式创建体力查询、挑战完成提醒、每日月报收集、每日签到或原神/绝区零抽卡分页委托，绑定当前调用插件、角色和真实宿主任务，期限最长 90 天；签到额外要求写入确认。每次准入重新验证并持久节流，默认不创建委托。抽卡分页只允许固定池、游标和页码，最少一秒间隔，AuthKey 始终留在账号插件；其他委托保持五分钟间隔。

只读代理还覆盖月报、挑战、特殊玩法与七圣召唤；临时活动 Cookie 不跨出账号插件。星铁小程序摘要当前仍受上游认证限制，失败不会删除或使正常 CK 失效。

## 公共查询用途

本人私聊 `共享查询账号 开启 [序号] [每日额度] [原神,星铁,绝区零]` 主动共享公开资料查询用途；默认每日 100、最多 1000，省略游戏时选择已绑定游戏。`共享查询账号 关闭 [序号]` 随时撤销。管理页只可关闭，不能代替本人开启。

公共池仍检查指定游戏插件的授权，仅代理固定公开基础资料，不返回出借账号身份或 CK。用途、索引与预算加密保存，北京时间零点重置额度，关闭/重开不返还当日次数；移除账号清除索引，迁移恢复清空公开用途。

## ark 授权令牌

原神与星铁插件的 ark 授权查询（授权额度、高级筛选、云面板等）需要机器人所有者的 ark 令牌。在账号管理页的“ark 授权令牌”中输入后，令牌与账号一样加密保存；游戏插件通过 `ark.request` 请本插件代发请求，拿不到令牌本身，只能用 `ark.status` 查询是否已配置。未配置时，ark 的匿名查询不受影响。

## 官方游戏签到

原神、星铁、绝区零的签到状态与奖励只读；实际签到要求明确确认，并先检查当天是否已经完成。验证码/首次绑定由用户在官方应用处理，不自动重复 POST。签到活动认证失败不把现有账号全局标记失效。游戏增强和定时策略仍由各游戏插件持有。

## 开发与构建

工具链沿用 RayleaBot：Go 1.26.6、Node 26.7.0、pnpm 11.22.0。Vue SDK 为构建依赖，打包后无需运行其他游戏插件。

```powershell
node scripts/prepare-ui.mjs C:/path/to/RayleaBot/sdk/vue
corepack pnpm --dir ui install --frozen-lockfile
go test ./...
corepack pnpm --dir ui test
corepack pnpm --dir ui run build
go run github.com/RayleaBot/RayleaBot/sdk/go/cmd/raylea-plugin build-go --backend ./cmd/mihoyo-accounts --target windows-x64 --include .rayleabot/source.zip=ui/source.zip
```

也支持 `linux-x64` 和 `macos-arm64`。打包前运行 `python scripts/source-bundle.py` 生成管理页提供下载的源码包。开发中的 Go SDK v0.7.1 尚未发布 tag，本机及源码包使用 `go.work` 指向随附 SDK，并在构建时设置 `RAYLEA_PLUGIN_BUILD_USE_WORKSPACE=1`。单独远端检出构建需要该 SDK 与编译期库版本或对应源码；当前 artifact 已包含后端、UI 与源码下载。

插件沿用 RayleaBot SDK 的 AGPL-3.0 许可，第三方依赖声明保留在 `LICENSES/`。

新增依赖只有本地二维码编码器 `go-qrcode`（避免把登录 URL 传给外部图片服务）及与宿主基线一致的 `x/sys`（Windows DPAPI）。数据库、加密、HTTP 与密钥派生使用宿主接口或 Go 标准库。

## 本人关联、设备和 Cookie 导入

主聊天身份私聊发送 `关联账号`，另一身份发送 `申请关联 编号`；回到主身份发送 `关联进度 编号` 核对目标，再按提示 `完成关联 编号 目标用户ID`。申请五分钟有效，双方确认后共享原始账号记录；`关联列表`、`解除关联 序号` 可查看或停止。解除后附属身份的后续查询与定时委托被拒绝。删除账号、公共账号授权仍由原始身份或管理操作处理。

设备设置只显示标识掩码，支持生成新标识或浏览器加密输入自定义标识，并清除缓存指纹。官方应用的设备验证仍由用户在官方应用完成。

管理页的“Cookie 与 SToken 导入”加密导入本人的米游社或 HoYoLab Cookie：国服需要 SToken（stuid、stoken 与 mid），或 LToken 与 CookieToken，与扫码得到的同一通行证合并为一个账号；海外可用 LToken 或 SToken v2/MID 换取凭据。按三游戏分步发现角色后保存。相同数字账号的国服/海外记录分开。支持固定海外战绩、签到、月报、养成、摹本、兑换与抽卡代理；AuthKey 只在本插件内换取。部分业务需要 CookieToken v2/MID。参考 [genshin.py 固定提交](https://github.com/seriaati/genshin.py/tree/075f0e1e332f9452e544aa7dfdf265678889d6ab)，海外真实账号仍需单独验收。

原神留影叙佳期的活动 Cookie 同样留在账号代理；领取由游戏管理页逐项明确确认。`账号帮助`、`账号版本` 读取随本版本编译的命令声明，锁库时仍可查看。
